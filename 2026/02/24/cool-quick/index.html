在日常工作中，你是否经历过这样的场景：复制了一段重要信息，切换窗口后却忘了粘贴；或者想找回之前复制的手机号，却发现剪贴板早已被覆盖？

传统的剪贴板只能保存一条记录，而市面上的剪贴板管理工具要么功能臃肿，要么体验割裂。于是我开发了 CoolQuick——一款智能、轻量的剪贴板管理工具，让笔记记录变得零摩擦。

1. 项目背景与设计理念

为什么选择剪贴板管理？

剪贴板是操作系统中最频繁使用的功能之一，却长期被忽视。据统计，一个普通办公用户每天复制粘贴的次数超过 50 次。然而，系统原生的剪贴板存在明显的痛点：

  • 易丢失：只能保存最后一条记录，新内容覆盖旧内容
  • 难追溯：无法查看历史记录，重要信息稍纵即逝
  • 无分类：所有内容混在一起，查找效率低下

设计理念：零摩擦体验

CoolQuick 的核心设计理念是 “零摩擦”——用户不需要改变任何使用习惯，复制内容后自动识别、自动分类，需要时一键调用。

如果你需要手动打开一个应用、点击保存按钮、再选择分类，那它就不是一个合格的剪贴板工具。

2. 技术架构选型

为什么是 Tauri？

在技术选型阶段，我对比了 Electron、Flutter 和 Tauri 三大跨平台方案：

特性 Electron Flutter Tauri
安装包体积 100MB+ 20-30MB 3-5MB
内存占用 300MB+ 100MB+ 30-50MB
原生性能 一般 较好 优秀
开发体验 熟悉 需学习 Dart Web 技术栈

最终选择 Tauri 的原因：

  • 极致轻量：使用系统 WebView，安装包仅 3-5MB
  • Rust 后端：高性能、内存安全，适合系统级操作
  • 前端友好：支持 React/Vue 等现代框架，开发效率高
  • 安全优先：默认启用 CSP，最小权限原则

整体架构

前端使用 React 18 + TypeScript + TailwindCSS + Zustand，后端使用 Rust + Tauri v1 + SQLite，通过 Tauri IPC 进行通信。

3.3 多窗口协作架构

CoolQuick 采用了独特的多窗口设计，每个窗口有独立的职责：

主窗口（Main Window）

  • 完整的笔记管理界面
  • Dashboard 统计可视化
  • 设置和规则配置

悬浮球（Floating Window）

  • 56x56 像素的迷你窗口
  • 始终置顶，贴边显示
  • 鼠标悬停展开抽屉

抽屉窗口（Drawer Window）

  • 快速浏览历史笔记
  • 支持搜索和类型筛选
  • 一键复制到剪贴板

弹窗（Popup Window）

  • 复制内容后的保存提示
  • 自动倒计时关闭
  • 支持手动/自动保存模式

6. 项目亮点总结

回顾 CoolQuick 的开发过程，有几个值得分享的设计决策：

技术层面

  • Tauri + Rust 的组合带来了极致的性能和体积优势
  • 多窗口架构实现了功能解耦，每个窗口职责单一
  • 事件驱动的通信模式，降低了前后端耦合度

产品层面

  • 零摩擦的设计理念，让用户无需改变使用习惯
  • 智能识别和分类，减少用户手动操作
  • 本地优先的数据策略，保护用户隐私

工程层面

  • 完整的 CI/CD 流程，自动化构建和发布
  • TypeScript 类型安全，减少运行时错误
  • Rust 的内存安全，避免系统级 Bug

7. 未来展望

CoolQuick 目前已经是一个可用的产品，但还有很大的提升空间：

  • 云同步：支持多设备数据同步（端到端加密）
  • 插件系统：开放 API，支持自定义内容处理器
  • 移动端：升级 Tauri v2，支持 iOS/Android
  • AI 增强：集成 LLM，实现智能摘要和标签建议
